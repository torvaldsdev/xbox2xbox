Инструкторское наставление для ИИ-агентов, строящих этот проект. Читай его
целиком перед первым изменением. Здесь нет декоративных строк: каждое правило

## 1. Миссия проекта

### 1.1 Что мы строим

**xbox2xbox — лучший слой совместимости Xbox Series X|S → Windows, который
только может быть.** Консольные тайтлы запускаются на Windows нативно, без
модификации их кода, из файлов, которые поставляет сам пользователь:

* x86-64 код тайтла исполняется внутри нашего процесса как есть (CPU консоли —
  Zen 2, та же архитектура);
* мы поставляем платформу под ним: системные API, GPU, шейдеры, файлы,
  аудио, ввод, сеть (offline), сохранения;
* данные тайтла конвертируются в формат хоста — заранее, где можно, и при
  первом использовании иначе.

GTA VI — тайтл, которым мы движем разработку сегодня. Сам слой — общий:
всё, кроме крейта `x2x-title`, платформенное и обязано работать с любым
тайтлом Xbox Series, а не только с этим.

### 1.2 Образец: VIctory

Образец лежит в `C:\Users\seant\Desktop\VIctory` (далее — «образец»). Это
работающий слой совместимости того же класса, что мы строим. Его состояние
на 2026-11-24 (из его README — сверяйся с актуальным):

| Стадия | Состояние образца |
|--------|-------------------|
| Загрузка, первые экраны (доступность, язык, настройки, правовые) | работает, 30 fps |
| Вступительное видео со звуком | работает |
| Стартовый экран, профиль, сохранения | работает |
| Загрузка в мир (~50 с) | работает |
| Мир (интро первой миссии) | рисуется и показывается: улицы, здания, транспорт, персонажи; 1–2 с на кадр; поверхности без освещения, полоса дальней геометрии отсутствует, персонажи местами сломаны |

Что образец уже умеет (это наш обязательный минимум): загрузчик PE с
crash-репортером; HLE консольных API с одним offline-пользователем,
лицензиями, пакетами и crash-safe сохранениями; чтение архивов и стриминга
с параллельной распаковкой zlib и BCPack; XInput-геймпады и
клавиатура-как-геймпад; XMA- и Opus-декодирование; D3D12.X поверх host D3D12
для меню и мира; трансляция консольных шейдеров GFX10 → DXIL (SM 6.6) с
дисковым кэшем и предсборкой ~27 000 пайплайнов; детайлинг консольных
текстур; режим Series S.

Чего образцу не хватает (наши цели, раздел 15): освещение, часть геометрии,
скорость кадров мира, ~300 нетранслированных шейдеров, 64-лейновые wave на
любом GPU, метаданные render-target, настоящие queries, depth bounds, HDR,
масштабирование, речь, реверберация, вибрация триггеров, мир Series S.

### 1.3 Что значит «полностью воссоздать и даже больше»

1. **Паритет обязателен.** Каждая подсистема образца должна быть воссоздана
   в xbox2xbox и доведена до его текущего уровня. «Мы сделали проще, потому
   что нам так удобнее» — не аргумент. Удобнее можно делать после паритета.
2. **Превосходство — цель.** После паритета каждой подсистемы — закрывай то,
   что образцу ещё не удалось (раздел 15), и делай лучше: быстрее, точнее,
   полнее, с большим покрытием тайтлов.
3. **Образец — не потолок.** Его архитектурные решения проверены практикой,
   но его ограничения — не наши ограничения. Если видишь решение лучше —
   предложи его владельцу с обоснованием, а не молча делай по-своему.

### 1.4 Три закона (в порядке приоритета)

1. **Репозиторий остаётся чистым.** Ничего из игр никогда не попадает сюда
   (правило №1, раздел 2.2).
2. **Консоль — спецификация.** Эмулируем наблюдаемое поведение, а не
   правдоподобие. Что консоль делает — то и мы делаем, включая «странные»
   детали.
3. **Сначала правильность, потом скорость.** Быстрый неправильный кадр — баг.
   Медленный правильный кадр — задача на производительность.

## 2. Железные правила

### 2.1 Границы записи

* **Пиши только внутри `C:\Users\seant\Desktop\xbox`** (рабочая область,
  корень репозитория xbox2xbox). Ни одного файла вне неё.
* **Образец `C:\Users\seant\Desktop\VIctory` — только чтение.** Изучай,
  грепай, читай — но никогда не пиши, не меняй, не коммить туда. Даже
  «безобидный» фикс в образце — нарушение.
* Файлы игры, кэши, конвертированные данные, дампы, логи с игровыми данными
  живут **вне репозитория**, в путях из конфига (раздел 10). Инструменты
  обязаны отказываться писать производные данные внутрь дерева исходников.
* Временные файлы экспериментов — тоже вне репозитория (или в `target/`,
  который игнорируется git). Никогда не клади «временный» дамп в корень.

### 2.2 Правило №1: политика ассетов

**Ничего из игры никогда не хранится в этом репозитории.** Всё строится на
машине пользователя из файлов, которые он поставляет. Это относится к
любому тайтлу, используемому для тестов, и ко всему производному от них — в
любой форме: файлы, строковые литералы, фикстуры, снапшоты, документация,
сообщения коммитов.

**Запрещено** коммитить, вставлять или генерировать внутри репозитория:

* ассеты: модели, текстуры, шейдеры, аудио, видео, тексты, архивы;
* исполняемый файл или любую его часть: секции данных, строки, таблицы,
  ресурсы, код — кроме сигнатур ниже;
* всё производное: конвертированные ассеты, дизассемблированный или
  декомпилированный код, дампы шейдеров, извлечённые таблицы, скриншоты.

**Разрешено:**

* наш собственный код, понимающий форматы;
* идентификаторы сборок: BLAKE3 исполняемого файла, CodeView GUID/age;
* per-build смещения хукаемых функций под именами, которые мы выбираем сами;
* байтовые сигнатуры, находящие функции или данные в исполняемом файле;
* небольшие константы интероперабельности (magic numbers, значения enum),
  которые мы пишем сами;
* синтетические тестовые данные, сгенерированные нашим собственным кодом.

**Единственное исключение** — константные таблицы формата BCPack (~78 КБ:
модели энтропии, таблицы рангов индексов, управляющие коды, словари
форматов). Без них BCPack-поток не декодируется, и вывести их нельзя. В
образце они лежат в `crates/victory-formats/src/bcpack-tables.bin` и
внесены в его чекер политики как исключение с обоснованием (решение
владельца образца, 2026-11-23; лицензия образца их не покрывает). Для
xbox2xbox действует то же исключение: перенеси файл из образца вместе с
записью-исключением в нашем чекере и явным решением владельца (пользователя)
— спроси его при первом переносе. Больше ничего подобного не принимается:
ни «ещё одна маленькая таблица», ни «только один заголовок».

**Три слоя защиты, которые нельзя обходить:**

1. `.gitignore` держит типовые данные вне `git status`.
2. `cargo xtask policy` — allowlist на каждый коммит (pre-commit hook):
   файл обязан иметь разрешённый тип, быть меньше 512 КиБ, не содержать
   бинарных данных и известных бинарных сигнатур, не содержать длинных
   hex/base64-последовательностей. Исключения требуют записи с обоснованием
   в `xtask/src/policy.rs`. Установка хуков: `cargo xtask install-hooks`.
3. В рантайме каждый писатель производных данных вызывает
   `x2x_core::ensure_outside_repo` до записи. Маркер `.x2x-root` в корне
   дерева исходников помечает его; проверка ловит и другие клоны/копии.

**Никогда** не перемещай, не переименовывай, не удаляй `.x2x-root`; не
обходи проверки, которые он обеспечивает; не ослабляй чекер политики, чтобы
«что-то прошло».

**Если игровые данные попали в git-историю:** последующий коммит — не
решение. Остановись, сообщи владельцу, перепиши историю
(`git filter-repo --path <file> --invert-paths`), force-push, все
ре-клонят. Утечка — единственная санкционированная перезапись истории, и
она требует одобрения владельца.

### 2.3 Код тайтла неприкосновенен

Различия поведения поставляет наш слой, а не патчи в коде тайтла.
Единственные касания кода тайтла — хуки, которые размещает `x2x-title`,
найденные per-build (по смещениям или байтовым сигнатурам). Никогда не
патчи байты тайтла, чтобы убрать симптом. Единственное исключение —
лёгкая подготовка образа загрузчиком (раздел 5.3), которая не меняет
исполняемый код.

### 2.4 Offline by design

Тайтл не может достучаться до сети. `x2x-hle::modules::net` отказывает в
сетевых путях; онлайн-области API отвечают как offline-консоль. Никогда не
добавляй путь, дающий тайтлу сеть, и не ослабляй host-политику DLL ради
«чтобы заработало». Если фикс требует этого — фикс неправильный.

### 2.5 Лицензия

xbox2xbox — **GPL-3.0-or-later**, как образец. Код, портированный из
образца, сохраняет лицензию и авторство: оставляй copyright-заголовки,
указывай происхождение в README/NOTICE. Файл `LICENSE` (GPL-3.0) создаётся
в фазе 0. Таблицы BCPack — исключение, лицензией не покрыты (раздел 2.2).

### 2.6 GPU-безопасность

Вход в мир на реальном GPU в ранних сборках образца вешал его; Windows
затем сбрасывает драйвер дисплея (все мониторы гаснут на момент). Это
реальный риск для машины пользователя.

* Перед любым запуском на реальном GPU — предупреди пользователя и получи
  согласие.
* Для рискованных экспериментов используй `X2X_D3D12_WARP=1` (программный
  адаптер: не может сбросить драйвер, но слишком медленный, чтобы дойти до
  мира за минуты).
* Долгие сборки (предсборка пайплайнов ~20 минут) — тоже предупреждай.

## 3. Образец VIctory: как изучать

### 3.1 Порядок чтения (первая сессия — обязательно)

1. `README.md` образца — статус, команды, отладочные переменные, требования.
2. `docs/architecture.md` — схема, роли крейтов, разрешение импортов,
   конвейер трансляции шейдеров.
3. `docs/asset-policy.md` — правило №1 целиком.
4. `Cargo.toml` корня — зависимости, линты, профили.
5. `.github/workflows/ci.yml`, `.githooks/pre-commit`, `xtask/` — что
   проверяется на каждый коммит.
6. Дальше — код подсистемы, которую строишь (раздел 5 даёт карту).

### 3.2 Карта соответствия имён

| Образец | xbox2xbox |
|---------|-----------|
| `victory-core` | `x2x-core` |
| `victory-pe` | `x2x-pe` |
| `victory-loader` | `x2x-loader` |
| `victory-hle` | `x2x-hle` |
| `victory-gpu` | `x2x-gpu` |
| `victory-shader` | `x2x-shader` |
| `victory-formats` | `x2x-formats` |
| `victory-pipeline` | `x2x-pipeline` |
| `victory-game` | `x2x-title` |
| `apps/victory` | `apps/x2x` |
| бинарь `victory.exe` | бинарь `x2x.exe` |
| `victory.toml` / `victory.example.toml` | `x2x.toml` / `x2x.example.toml` |

Структура модулей внутри крейтов зеркалит образец один-в-один, чтобы код
можно было изучать рядом. Имена типов и функций сохраняй, где это разумно:
это ускоряет и изучение, и портирование.

### 3.3 Метод прослеживания фичи

Прежде чем писать подсистему, проследи в образце полный путь одной фичи:

1. Найди точку входа: импорт тайтла (`census`/`inspect` в образце или grep
   по `hle_export!`), или команду CLI, или вызов D3D12.X.
2. Пройди путь до реализации: модуль HLE → объект GPU → команда списка →
   host D3D12; или контейнер шейдера → decode → IR → emit → DXIL.
3. Прочитай тесты рядом с реализацией — они фиксируют контракт.
4. Выпиши контракт (входы, выходы, инварианты, краевые случаи) и только
   потом пиши наш код.

Пример: `GetModuleFileNameW` в `victory-hle/src/modules/kernel.rs` —
очищает last error при успехе, ставит `ERROR_INSUFFICIENT_BUFFER` при
усечении, возвращает размер буфера. Тайтл отличает усечённое имя от целого
именно по этому. Такие детали — и есть работа.

### 3.4 Что можно заимствовать, что нельзя

* **Можно:** код образца (GPL, с сохранением авторства), архитектурные
  решения, описания форматов, контракты API, конвенции, тестовые подходы.
* **Нельзя:** ничего игрового и производного от игр — даже если оно лежит
  в кэше образца вне его репозитория. Наши кэши строятся из файлов
  пользователя на его машине.
* **С осторожностью:** «шорткаты» образца, помеченные в его коде
  комментариями `shortcut:` — это известные упрощения. Переноси их только
  осознанно, с записью в наш список известных упрощений (раздел 15), и никогда
  не выдавай за полноценную реализацию.

## 4. Архитектура xbox2xbox

### 4.1 Схема

```
 файлы пользователя (вне репо)            xbox2xbox
 ───────────────────────────             ─────────────────────────────────────────
 ассеты игры ──────────────────────────► x2x-pipeline + x2x-title
                                         (x2x-formats, x2x-shader)
                                                    │
                                                    ▼
                                         cache_dir: конвертированные данные
                                                    │
 исполняемый файл ─► x2x-loader ───────► код тайтла (нативный x86-64)
                    prepare, map, bind      │ импорты
                                            ▼
                                         x2x-hle ── host Windows (общие API)
                                            │ D3D12.X
                                            ▼
                                         x2x-gpu ─► host D3D12
                                            │ шейдеры при создании пайплайна
                                            ▼
                                         x2x-shader ◄─► cache_dir
```

Шейдеры транслируются, когда тайтл создаёт пайплайн, из байтов, которые он
передаёт, откуда бы он их ни загрузил (exe, архив, память). Предварительная
конвертация из файлов (`x2x translate --cache`) — только прогрев: она
заполняет тот же кэш под тем же ключом. С `--pipelines` она также собирает
host-пайплайны пакета шейдеров тайтла в библиотеку пайплайнов, из потоков
создания, которые передал бы движок (`x2x-title` строит их, `x2x-gpu`
читает их так же, как читает потоки тайтла), так что запуск находит их под
именами, которые даёт сам.

### 4.3 Крейты

| Крейт | Роль |
|-------|------|
| `x2x-core` | конфиг, страж политики ассетов, логирование |
| `x2x-pe` | read-only анализ PE32+ и import-библиотек |
| `x2x-loader` | prepare, map, bind и старт образа тайтла; TLS-редирект; crash-репортер |
| `x2x-hle` | реализации консольных API (`src/modules/`, по файлу на DLL), политика host pass-through |
| `x2x-gpu` | объекты D3D12.X, командные списки, память GPU → host D3D12 |
| `x2x-shader` | консольные контейнеры шейдеров → DXIL: decode `gfx10/`, анализ `ir`/`structure`/`range`/`resource`, lowering `emit/` (тесты рядом) |
| `x2x-formats` | тайловые раскладки текстур и детайлинг, BCPack, XMA2, Opus, zlib |
| `x2x-pipeline` | трейт конвертера, content-addressed кэш |
| `x2x-title` | специфика GTA VI: форматы, идентификаторы сборок, хуки — **единственное место, где живёт знание о конкретной игре** |
| `apps/x2x` | CLI (`inspect`, `census`, `lib-exports`, `shader-info`, `translate`, `run`, `config`) |
| `xtask` | проверка политики ассетов, git-хуки |
| `tests/fixtures/probe` | наш собственный «тайтл»-заменитель для тестов загрузчика |

Всё, кроме `x2x-title`, — платформенное и тестируемо на любом тайтле Xbox
Series.

### 4.4 Правила зависимостей

* Направление зависимостей: `core` ← все; `pe` ← `loader`; `loader` ← `hle`;
  `gpu` ← `hle` (модуль d3d12x); `shader` ← `gpu`; `formats` ← `pipeline`,
  `shader`, `title`; `pipeline` ← `title`, CLI; `title` ← CLI.
  Никаких циклов; никаких зависимостей платформенных крейтов от `x2x-title`.
* Если «платформенный» фикс требует `if это GTA VI` вне `x2x-title` —
  дизайн неправильный. Ищи общее правило.
* Зависимости — только через `[workspace.dependencies]` корня, версии
  пиннятся как в образце (anyhow, thiserror, clap, tracing,
  tracing-subscriber, serde, toml, object, windows-sys, windows,
  windows-core, blake3, memchr, miniz_oxide, walkdir, tempfile, opus-pure).
  Новая внешняя зависимость — обоснуй владельцу: лицензия, вес, зачем.

### 4.5 Разрешение импортов (порядок не менять)

Для каждого `dll!function`, который импортирует тайтл:

1. наша реализация в `x2x-hle::modules` (всегда выигрывает);
2. функция самого хоста, если `HostPolicy` разрешает эту DLL;
3. экспорт DLL, которую тайтл поставляет рядом с exe (маппится как exe;
   только DLL, не обслуживаемые пунктами 1–2);
4. сгенерированная заглушка, называющая импорт при вызове
   (`run --unimplemented trap` — брейк в отладчик и abort; `zero` — лог
   один раз и возврат 0).

`LoadLibrary*` консольной DLL, которую мы реализуем (например
`xgameruntime.dll`), возвращает псевдо-handle; `GetProcAddress` на нём
находит наши функции. `LoadLibrary*` DLL тайтла возвращает её
смаппленный образ (маппя при первом использовании, если никто не
импортирует). По имени, как и по импорту, тайтл получает только host-DLL,
пропущенные `HostPolicy`, и `GetProcAddress` на такой DLL возвращает наш
override там, где import binding вернул бы его. `QueryApiImpl` выдаёт наши
runtime-объекты по provider и interface id (`x2x-hle::modules::xgameruntime`
перечисляет области); онлайн-области отвечают как offline-консоль.

Хранилище тайтла — диск на консоли, и тайтлы строят пути на нём.
`x2x-hle::modules::files` привязывает каждый path-taking импорт тайтла
(kernel32 и C/C++ runtime) и переписывает пути на виртуальном диске в
host-папку за ним; persistent local storage — один такой диск над папкой
под `X2X_DATA_DIR`. Остальные пути доходят до хоста без изменений.

### 4.6 Модель консоли

Тайтлы выбирают настройки (разрешение, бюджеты памяти) по модели консоли,
поэтому её выбирает пользователь; по умолчанию Series X.

| Параметр | Series X | Series S |
|----------|----------|----------|
| Память тайтла (GPU-optimal, standard) | 10 GiB, 3.5 GiB | 0, 7776 MiB |
| Compute units GPU | 52 | 20 |

Значения — из `victory-gpu/src/console.rs` образца. Переноси как есть;
известное упрощение образца: более поздние системные обновления дали
Series S больше памяти (точная цифра не опубликована); GTA VI не
сайзится от этой цифры (идёт по типу устройства). Обновляй, если тайтл
сайзится.

## 5. Спецификации подсистем

Каждая спецификация: что делает, ключевые механизмы, контракт, что
смотреть в образце. Это обязательный минимум паритета.

### 5.1 x2x-core

Общая обвязка всех крейтов и инструментов. Образец: `crates/victory-core`.

* `config`: где живут файлы пользователя (никогда внутри репозитория).
  Поля: `game_dir`, `cache_dir`, `data_dir`, `fidelityfx_dir`,
  `test_titles`. Переменные окружения имеют приоритет над файлом;
  `X2X_CONFIG` выбирает другой файл конфига. `require_game_dir()` —
  явная ошибка, если путь не задан.
* `policy`: рантайм-половина правила №1. `ensure_outside_repo(path)`:
  отказ, если путь внутри дерева, из которого собран бинарь, или если
  любой предок содержит маркер `.x2x-root` (ловит другие клоны).
  Каноникализирует longest existing prefix, чтобы несуществующие пути
  тоже сравнивались; `..` в несуществующем хвосте резолвится лексически.
  Тесты: отказ внутри репо, отказ `..`-escape, отказ чужого клона по
  маркеру, принятие посторонних директорий.
* `logging`: одна настройка tracing для всех бинарей. Формат
  `X2X_LOG=<target>=debug,...`; release логирует info и выше.

### 5.2 x2x-pe

Read-only анализ PE32+ (x86-64) образов и COFF import-библиотек. Образец:
`crates/victory-pe`. Тайтлы Xbox Series — обычные x86-64 PE32+ (CPU
консоли Zen 2), поэтому один парсер служит тайтлам, консольным системным
DLL и host-бинарям.

* Никогда ничего не модифицирует; патчинг живёт в `x2x-loader`, который
  использует сырые смещения из `layout`.
* Типы: `ImageInfo`, `SectionInfo`, `ImportModule`, `ImportEntry`,
  `ImportSymbol` (Name с hint / Ordinal), `ExportInfo`, `TlsInfo`,
  `CodeViewInfo` (GUID/age — идентификатор сборки).
* Ошибки: `Unsupported` (валидный PE, но не наш — 32-bit, ARM64),
  `Malformed` (обрезан или противоречив).
* `implib`: пары `dll!export`, которые описывает import-библиотека
  (CLI `lib-exports`).

### 5.3 x2x-loader

Запускает оригинальный x86-64 код тайтла нативно, внутри нашего процесса.
Образец: `crates/victory-loader`. Машинный код не нуждается в трансляции —
отличается платформа под ним. Работа загрузчика:

1. **`prepare()`** — чисто и переносимо: слегка подготовленная копия
   образа. Пометить как DLL, убрать entry point и import directory,
   отсоединить TLS callbacks — чтобы загрузчик Windows смаппил образ,
   релоцировал его, выделил статический TLS и зарегистрировал unwind
   таблицы, но **не исполнил ни строки его кода и не разрешил ни одного
   импорта**.
2. Загрузить копию как настоящий модуль (Windows-only): отладчики,
   профайлеры, crash-дампы и stack walks видят его.
3. Смаппить DLL, которые тайтл поставляет рядом (`load_title_dlls`),
   тем же способом.
4. Привязать каждый импорт самостоятельно через `ImportResolver`: наш рантайм
   (`x2x-hle`), хост или DLL тайтла; неразрешённое — в сгенерированную
   заглушку, точно сообщающую, что было вызвано (`UnimplementedPolicy`).
5. Инициализировать DLL тайтла, затем TLS callbacks и entry point на
   потоке с размером стека, который просит образ; с этого момента
   передавать каждый старт и конец потока прикреплённым образам.

Ключевые детали:

* **TLS-редирект**: код exe достаёт свой статический TLS как слот 0;
  смаппленный как DLL он получает другой слот — загрузчик перенаправляет
  эти загрузки (`tls`).
* **Crash-репортер** (`crash`): необработанные исключения, паники и host
  GPU failures пишутся в `crashes.log` в data-папке; fault именуется
  `module+rva`, стек faulting-потока разматывается. First-chance
  breakpoints — под `X2X_CRASH_BREAKPOINTS=1`.
* **Заглушки** (`thunks`): называют импорт при вызове; считают вызовы.
* `run` без `--execute` маппит образ и его DLL, не стартуя тайтл;
  `census` классифицирует импорты, ничего не маппя.

### 5.4 x2x-hle

Реализация поверхности консольного системного API. Образец:
`crates/victory-hle`. Тайтл импортирует из трёх видов DLL, у каждого своя
политика:

| Вид | Примеры | Кто обслуживает |
|-----|---------|-----------------|
| Windows API sets, общие с PC | `api-ms-win-core-synch-*`, `ws2_32.dll` | host pass-through, override здесь, где консольное поведение отличается (пути, память) |
| консольные системные API | `xgameruntime.dll`, `xmem.dll`, `d3d12_xs.dll` | реализованы здесь, в `modules` |
| всё остальное | | заглушка неимплементированного импорта из загрузчика |

**Добавление API:** напиши `extern "system"` функцию с именем в точности
как импорт, затем перечисли её через `hle_export!` в `module()` модуля.
`cargo xtask`-независимый `x2x census` по тайтлам показывает, чего ещё не
хватает. Реестр code-only: исход `Missing` проверяем на любом хосте; сам
host pass-through требует Windows.

Модули (зеркалим `victory-hle/src/modules/`):

| Модуль | Назначение |
|--------|-----------|
| `kernel` | overrides общих Windows API, где консольный смысл иной: `GetModuleHandle*` (NULL → образ тайтла), `GetModuleFileName*` (контракт усечения), `LoadLibrary*`/`GetProcAddress` (псевдо-handles, образы тайтла), пути |
| `files` | привязка path-taking импортов, виртуальные диски → host-папки |
| `xgameruntime` | `XGameRuntimeInitialize`, `QueryApiImpl` по provider/interface id, области: пользователи, лицензии, пакеты, сохранения, UI, сеть… |
| `xuser` | один подписанный offline-пользователь |
| `xpackage` | пакеты, лицензии |
| `xgamesave` | сохранения: файлы под data-dir, **crash-safe на каждом шаге записи** |
| `xgameui` | диалоги (ввод текста и др.) |
| `xgame` | игровые runtime-области |
| `xstore` / `xnetworking` | онлайн-области отвечают как offline-консоль |
| `xsystem` | системная информация |
| `xmem` | консольные аллокации памяти |
| `xasync` | асинхронные задачи, `XTaskQueue` |
| `gameinput` | XInput-геймпады, клавиатура, клавиатура-как-геймпад |
| `audio` | XAudio2-подобный путь: XMA-голоса, Opus-потоки |
| `dsp` / `apu` | DSP-обработка, аудио-юнит |
| `speech` | синтез речи (в образце молчит — наша цель) |
| `media` | медиа-фундамент (видео со звуком) |
| `d3d12x` | мост к `x2x-gpu` |
| `display` | окна тайтла, показ через stand-in, читающий сообщения |
| `dstorage` | DirectStorage-стриминг |
| `fidelityfx` | AMD FidelityFX: host-путь (PC DLL) и консольный путь |
| `lifecycle` | жизненный цикл тайтла (suspend/resume/relaunch) |
| `net` | offline by design: отказ сети |
| `rpcrt4` | GUID-вызовы RPC наши (`UuidCreate*`, `UuidToString*`, `RpcStringFree*`); сама DLL вне host-политики — её `ws2_32` импорты были бы сетевым путём, который `net` не увидит |

| `xg` | консольная графика (низкоуровневая) |

Планируемые области образца (движутся результатами census, а не
полнотой): `file` (пути пакетов), `thread` (TLS callbacks для потоков
тайтла), `xaudio2`, заглушки `xstore`. Наши — те же, плюс то, что покажет
наш census.

**HostPolicy** (`host.rs`): какие host-DLL пропускаются. Консольные DLL
никогда не pass-through. Override выигрывает у хоста там, где import
binding вернул бы его.

### 5.5 x2x-gpu

D3D12.X на host D3D12. Образец: `crates/victory-gpu`. Самая большая
подсистема; строй её по модулям образца.

**Модель команд:** D3D12.X записывает команды из кода, инлайненного в
тайтл: тот пишет пакеты в командный список, пока put pointer ниже лимита,
и вызывает метод списка иначе. Наши списки держат лимиты нулевыми, так что
каждая команда приходит сюда вызовом и исполняется на host D3D12.
GPU-адреса тайтла — CPU-адреса (память консоли unified).

Модули (зеркалим):

| Модуль | Назначение |
|--------|-----------|
| `device` | объект устройства, который создаёт тайтл |
| `dxgi` | адаптерная сторона, swap chain |
| `resource` | heaps и ресурсы |
| `fence` | fences (отвечают и за `ID3D12Fence1`) |
| `queue` | командные очереди |
| `list` | командные аллокаторы и списки |
| `descriptor` | дескрипторные heaps (+ `host` — host-представление) |
| `root` | root signatures |
| `query` | query heaps |
| `signature` | командные сигнатуры (indirect) |
| `pipeline` | состояния пайплайнов (+ `host`, `library`, `make`) |
| `frame` | frame pacing |
| `object` | общее всех консольных графических объектов |
| `console` | модель консоли (раздел 4.6) |
| `external` | host-библиотеки, пишущие в списки тайтла (FidelityFX) |
| `bindless` | views, которые шейдеры выбирают из heap сами |
| `memory` | память GPU: page table для title memory по сырым адресам |
| `shadow` | теневые копии: только изменённая память тайтла копируется |
| `twin` | writable twins для depth-текстур |
| `texture` | консольные текстуры → host |
| `sampler` | сэмплеры |
| `indirect` | indirect-исполнение, бюджет в порядке записи |
| `draw` | запись draw-вызовов |
| `primitive` | топология, rectangle lists через geometry shader |
| `shader_cache` | дисковый кэш трансляций |
| `switch` | переключения состояний |
| `tdr` | обработка GPU failure / device removal |
| `watch` | журнал изменений памяти тайтла (`kernel_will_write`, `title_memory_aliased/remapped`) |
| `capture` / `copystat` | диагностика (feature `diagnostics`) |
| `host` | host-устройство, `on_failure` |

**Ключевые механизмы (контракты паритета):**

* **Память тайтла по сырым адресам** — через page table: шейдеры, читающие
  title memory по адресу (ray-tracing структуры), получают доступ через
  неё. Root views программ, использующих title memory, идут через page
  table.
* **Теневые копии и журнал изменений**: на host копируется только
  изменённая память тайтла. Шейдеры помечают страницы, которые пишут через
  views; copy-back сравнивает только помеченные; помеченная страница не
  сохраняет саму себя при собственном copy-back. Heap-записи, копируемые
  как байты, зеркалятся; views вне элементов своего буфера получают
  собственную копию; heap-слот держит собственную копию своего view.
* **Одна host-текстура на память текстуры**; writable twins для
  depth-текстур; depth пишется из compute.
* **Null views** для title buffer views, пустых или выходящих за копию.
* **Bounded root views** и страж против текстурных дескрипторов, читаемых
  как буферы.
* **Indirect**: бюджет заряжается в порядке записи и не wraps; indirect
  вызов дропается до clamp, не после.
* **Библиотека пайплайнов**: предсобранные или собранные worker-потоками
  пайплайны хранятся на диске; библиотека принадлежит GPU и драйверу, на
  которых сделана. Атомарные записи сериализуются уникальными temp-файлами.
* **Swap chain**: throttling неудачных созданий и resize; retries не
  спиннят бесконечно.
* **Device removal**: `GetDeviceRemovedReason` сообщает состояние
  host-устройства, а не `E_NOTIMPL`; при GPU failure — DRED-детали (какой
  аллокация задета, какие команды в полёте).
* **Frame pacing**: кадр показывается в темпе тайтла; известные проблемы
  образца — дрейф на одном экране в release (наша цель — исправить).

### 5.6 x2x-shader

Консольные шейдеры Xbox Series → host-шейдеры. Образец:
`crates/victory-shader`. Сердце проекта; точность здесь — закон.

**Контейнеры:** шейдер Xbox Series — стандартный DXBC-контейнер (`dxbc`).
Его `DXIL`-часть (`dxil`) может нести консольные добавки вокруг LLVM
bitcode: таблица `XDAT` перед ним, индексирующая блобы после него, среди
них `xbop` (опции компилятора) и zlib-сжатый GFX10-код. Bitcode может
использовать консольные intrinsics, поэтому GFX10-код транслируется в
общем случае.

**Конвейер трансляции** (порядок стадий — как в образце):

1. `gfx10` — decode машинного кода RDNA2: opcodes, fields, sp3.
2. `ir::build` — один-в-один SSA: каждая машинная инструкция → один `Inst`
   (кроме scheduling-only: `s_nop`, `s_waitcnt*`, `s_inst_prefetch`… и
   избыточных условных переходов). Каждый dword регистра — переменная:
   чтение именует `Value`, запись определяет новый, `Phi` сливают значения
   на стыках control flow. Ничего не поднимается: инструкция сохраняет
   opcode и декодированные поля, точная семантика остаётся при ней.
   Неявные операнды явны: SCC, M0, EXEC (читает каждая векторная
   инструкция). Запись VGPR также читает старое значение регистра —
   лейны, выключенные в EXEC, сохраняют его. M0-relative доступ
   (`v_movrels/d/sd_b32`, `v_swaprel_b32`) именует весь возможный диапазон.
3. `structure` — убирает EXEC: lane masks → per-lane булевы, wave-wide
   mask tests → per-lane ветвления; векторная инструкция сохраняет guard
   только там, где лейн может дойти до неё с EXEC-битом, сброшенным в
   clear.
4. `range::build` — прогоняет обе стадии снова там, где граница индекса
   register-relative move (`v_movrel*`) доказана на per-lane форме, так
   что move именует только регистры, которых может достичь.
5. `resource` — трассирует каждый дескриптор и scalar memory address до
   root-параметра, откуда он происходит (table, heap, root descriptor или
   constant). Дескриптор, читаемый waterfall loop из первого лейна
   (`v_readfirstlane_b32`), трассируется до per-lane load или choice,
   дающего каждому лейну свой (`v_cndmask_b32` маски, или if/else, чьи
   ветви каждая задаёт его: трассировка по путям лейнов из
   структуризации), и доступ с non-uniform heap index за один проход.
6. `emit` — DXIL-эмиссия: консольный vertex/pixel/compute/mesh шейдер как
   PC DXIL-контейнер (SM 6.6), который host D3D12 принимает. Compute
   сохраняет thread-group size консоли; зависящий от lane layout
   (cross-lane операции) объявляет wave size консоли (`WaveSize`) —
   host-устройство обязан его поддерживать.

**Контракт host-биндинга** (`emit`, `HostShader`) — переноси дословно из
образца, это выстраданный контракт:

* **User data** в `b0, space 0` (32-bit root constants или constant buffer,
  по стадии): dword `index` держит значение root-параметра. Root-constant
  dword — константа. Descriptor table — байтовое смещение первого
  дескриптора в heap: индекс × 32 для CBV/SRV/UAV таблиц, × 16 для sampler
  (консольные размеры дескрипторов; код добавляет смещения в этих
  единицах). Heap bases динамических ресурсов — 0 и не перечислены.
* **Дескрипторы** через SM 6.6 `ResourceDescriptorHeap[]` и
  `SamplerDescriptorHeap[]`, по индексу, который даёт консольный адрес —
  host heaps сохраняют порядок дескрипторов тайтла. Root signature
  требует `CBV_SRV_UAV_HEAP_DIRECTLY_INDEXED` и
  `SAMPLER_HEAP_DIRECTLY_INDEXED`.
* **Immediate samplers** как static samplers `s<n>, space 0`; comparison
  sampling: immediate с comparison filter (бит 0x80), heap sampler должен
  быть comparison на хосте; один из двух immediate, выбранный uniform
  control flow, занимает две записи — сэмплирование бежит с обеими,
  результат выбирается.
* **Root CBVs** как root descriptors `b<i>` в `ROOT_CBV_SPACE`.
* **Root SRV/UAV** (raw buffers) — resource-heap views, которые делает
  host: raw view всей host-копии, держащей root-адрес, по heap-индексу,
  который host пишет в user-data запись `ROOT_SRV_VIEW`/`ROOT_UAV_VIEW`;
  байтовое смещение root-адреса в копии — в запись `ROOT_VIEW_OFFSET`.
  Шейдер добавляет это смещение к каждому читаемому offset. Host root
  descriptors не имеют границ: через view чтение за копией даёт 0, запись
  дропается. Один view на host-копию (и вид) обслуживает все draw списка.
  В программах с title memory root SRV/UAV — сама title memory.
* **Vertex fetch**: mesh/vertex программы сами фетчат вершины
  typed-format loads (`tbuffer_load_format_*`): формат в инструкции,
  трансляция читает сырые байты и конвертирует сама. Дескрипторы вокруг
  root SRV (stride 1, без record limit). Индекс вершины, stride и offset
  атрибута — арифметика самого шейдера на данных буфера (per-stream
  заголовки), не поля дескриптора.
* **Buffer views в heap** объявляются тем, как шейдер их читает: raw
  (ByteAddressBuffer) для dword loads/stores, atomics и typed-format loads
  без индекса; structured со stride used-resource записи при индексации;
  typed с четырьмя 32-bit float каналами для `buffer_load/store_format_*`.
  Host view по этому индексу обязан быть того же вида и стартовать с
  базового адреса консольного дескриптора (raw: `R32_TYPELESS` с raw
  flag), каким бы ни был вид дескриптора тайтла. Буферы, читаемые по
  элементам через resource heap (без used-resource записи, без stride) —
  тоже raw, адресация элемент × stride view + offset, stride из
  view-stride таблицы.

**Кэш и идентичность:** `SOURCE_HASH` — хэш того, из чего собран
транслятор: его исходники, манифест и build script, lockfile воркспейса и
версия компилятора. Кэши трансляций ключатся на нём — изменённый
транслятор никогда не выдаёт старую трансляцию.

**Точность — закон:** float-режим консоли — спецификация: f16-округление,
denormals, signed zeros, `med3`, `op_sel`/`omod`/`clamp`, EXEC lane masks.
Никогда не чини одну инструкцию, ломая семантику другой; сначала пинни
поведение тестом (`emit/*_tests.rs` сравнивают с float-режимом консоли).
Fused multiply-add, следующие host GPU, — известное принятое отклонение
образца; не «чини» молча.

**Покрытие образца (наш ориентир):** mesh 8765/8765, vertex/pixel
12550/12592, compute 2579/2637; не хватает merged geometry stages (195
программ) и ~100 других; часть compute требует GPU с 64-лейновыми waves.
`x2x translate` прогоняет каждый найденный шейдер (контейнеры, SGD5) через
конвейер и перечисляет, что пока не может.

### 5.7 x2x-formats

Платформенные форматы данных, общие для всех тайтлов Xbox Series. Образец:
`crates/victory-formats`. Каждый модуль чист (байты на входе, байты на
выходе, без I/O):

* `texture` — тайловые раскладки текстур GPU (размеры, tiling) и копии
  между тайловым и линейным представлением (детайлинг/ретайлинг).
  Тесты образца сверяют раскладки с размерами и адресами самого addrlib —
  перенеси подход. Не хватает образца: метаданные render-target planes
  (наша цель).
* `bcpack` — декодирование BCPack (+ таблицы-исключение, раздел 2.2).
* `xma` — XMA2-декодирование голосов (+ таблицы `xma/tables.rs`).
* Opus — через `opus-pure` (BSD-3-Clause, pure Rust). Результаты образца
  не верифицированы против тайтла — наша цель: верифицировать.
* zlib — через `miniz_oxide` (аппаратная распаковка консоли).

### 5.8 x2x-pipeline

Offline-конвертация данных игры пользователя в host-форматы. Образец:
`crates/victory-pipeline`. Всё здесь бежит на машине пользователя, читает
его файлы и пишет в его кэш. Ничего произведённого здесь не коммитится:
производные данные — всё ещё игровые данные.

Единица работы — `Converter`: байты на входе, байты на выходе,
детерминированно. Результаты хранятся в content-addressed `Cache`,
ключённом на id конвертера, версию конвертера и входные байты — повторный
прогон после обновления игры или фикса конвертера переделывает только
изменившееся.

```rust
pub trait Converter: Send + Sync {
    fn id(&self) -> &'static str;      // стабильный, часть ключа кэша
    fn version(&self) -> u32;          // bump при изменении выхода
    fn convert(&self, input: &[u8]) -> anyhow::Result<Vec<u8>>;
}
```

### 5.9 x2x-title

Всё специфичное для GTA VI: форматы контейнеров, идентификаторы сборок,
хуки в его коде (по per-build смещениям или байтовым сигнатурам). Образец:
`crates/victory-game`. Что можно и нельзя хранить здесь — определяет
политика ассетов.

* `KnownBuild` / `KNOWN_BUILDS`: label (наш, например «Series 1.0.2.1»),
  BLAKE3 оригинального exe (hex), `startup_archive` (RPF9-архив, нужный
  при старте, рядом с exe — `appdata0.rpf`). `identify(blake3_hex)` —
  поиск сборки по хэшу.
* `shaderpack` — пакет шейдеров: кэш пайплайнов движка, поставляемый рядом
  с базами шейдеров. Каждая запись — один пайплайн, как его сериализует
  консольный драйвер (register packet, метаданные пайплайна и, на
  аппаратную стадию, нативная программа с метаданными), ключённый
  собственными хэшами движка. Layout (little-endian): header 0x80 B
  (magic `PS\0\x09`, char[32] driver build, char[36] compiler version,
  +0x48 u64 fingerprint базы шейдеров, u32 graphics/compute/blob/program
  count, u32 blob/program bytes); graphics 0x70 B (u64 key, u32 packet
  blob, u32 metadata blob, u64 vertex-or-mesh shader hash, u64 pipeline
  hash, u64 depth-stencil/rasterizer/blend state hashes, 7 × {u32 program,
  u32 program metadata blob}: PS VS GS ES HS LS fetch); compute 0x18 B;
  blob/program таблицы (u32 offset, u32 size); blob data, затем program
  data (программы на 256-байтовых смещениях). Отсутствующие индексы —
  `u32::MAX`. Хэши шейдеров — те, что база хранит после каждого packed
  контейнера; хэши состояний — 64-bit CityHash (v1.1) компактных описаний
  состояний движка. Graphics metadata также несёт часть описания
  пайплайна: +0x10 восемь render-target форматов (DXGI, по байту), +0x1c
  sample mask, +0x24 depth format, RT count, topology type; +0x28 sample
  count/quality; +0x38 размер input layout на +0x4c (u32 element count,
  затем на элемент: u32 длина имени с NUL, имя, u32 semantic index,
  format, input slot, byte offset, slot class, step rate).
* `sgd5` — база шейдеров движка: effects, techniques, passes.
* `cityhash` — CityHash v1.1 для хэшей состояний.
* `pipelines` — построение потоков создания пайплайнов из записей пакета
  (то, что передал бы движок; `x2x-gpu` читает их как свои).

### 5.10 apps/x2x — CLI

Каждая команда читает файлы пользователя и пишет только в stdout или в
его cache-директорию (вне репозитория). Команды (зеркалим образец):

```
x2x inspect <exe|dll> [--imports] [--exports]
x2x census [paths...] [--missing] [--strict]
x2x lib-exports <import.lib> [--list]
x2x shader-info [paths...] [--verbose] [--disasm] [--effects]
x2x translate [paths...] [--validate] [--pipelines] [--list] [--jobs N]
x2x translate [paths...] --cache [--pipelines] [--jobs N]
x2x run <exe> [--execute] [--unimplemented trap|zero] [--strict]
            [--console series-x|series-s] [-- <аргументы тайтла>]
x2x config
```

* `inspect` — резюме одного PE: заголовки, секции, импорты, TLS, build id.
* `census` — агрегат импортов всех PE под путями: что покрыто нашим
  рантаймом; `--strict` не считает host pass-through покрытием;
  `--missing` перечисляет отсутствующие `dll!function`, частые первыми.
* `shader-info` — контейнеры шейдеров в файлах/директориях (и внутри
  архивов движка, если несжаты), их layout; паки — последними, стадии по
  найденным контейнерам; `--effects` — effects баз шейдеров.
* `translate` — прогон всех найденных шейдеров через транслятор, отчёт о
  непокрытом; `--cache` — прогрев дискового кэша; `--pipelines` — сборка
  библиотеки пайплайнов; повторный пропуск существующего за секунды;
  прерванный — сохраняет сделанное.
* `run` — запуск; `--execute` реально стартует тайтл и ставит
  crash-репортер; проверяет читаемость RPF9-заголовка startup-архива до
  старта.
* `config` — проверка путей.

### 5.11 xtask

Обслуживание репозитория. `cargo xtask <command>`:

* `policy [--staged]` — проверка политики ассетов (раздел 2.2): allowlist
  типов (`rs toml md txt lock yml yaml json hlsl hlsli ps1 cmd sh` +
  имена `.gitignore .gitattributes .editorconfig .x2x-root pre-commit
  LICENSE …`), лимит 512 КиБ, запрет бинарных сигнатур (MZ, DXBC, DDS,
  RIFF, LLVM bitcode, PDB, архивы, zip, 7z, cabinet, MSI/OLE), NUL-байтов,
  длинных hex/base64-ран (>512 символов) и hex-литералов. Исключения —
  записи с обоснованием. Тест `repository_passes_policy` прогоняет
  проверку везде, где бегут тесты, даже в клонах без хука.
* `install-hooks` — `git config core.hooksPath .githooks`.

## 6. Дорожная карта

Работай фазами. Каждая фаза заканчивается критериями приёмки; без них —
не закончена. Не перепрыгивай: фундаментальные ошибки ранней фазы
дорожают экспоненциально. Параллелить можно независимые подсистемы одной
фазы (например formats и HLE-модули), но не фазы.

### Фаза 0 — Скелет (никакого кода платформ)

Создать: workspace `Cargo.toml` (resolver 3, edition 2024, линты и профили
как в образце), `rust-toolchain.toml` (pinned, targets
x86_64-pc-windows-msvc, components rustfmt+clippy), `rustfmt.toml`
(max_width 100, field_init_shorthand), `.gitignore`, `.gitattributes`,
`.x2x-root`, `LICENSE` (GPL-3.0), `README.md` (статус: «скелет»),
`docs/architecture.md`, `docs/asset-policy.md` (адаптация правила №1),
`x2x.example.toml`, `.cargo/config.toml` (alias xtask), `.githooks/pre-commit`,
`.github/workflows/ci.yml`, `xtask` (policy + install-hooks + тесты),
`x2x-core` (config, policy, logging + тесты), пустые крейты-заглушки с
`//!`-доками ролей, `tests/fixtures/probe`.

**Приёмка:** `cargo test --workspace` зелёный (включая
`repository_passes_policy`); `cargo clippy --workspace --all-targets
--locked -- -D warnings` чистый; `cargo xtask policy` проходит; хуки
установлены; git-репозиторий инициализирован, первый коммит сделан.

### Фаза 1 — PE и загрузчик

`x2x-pe` (image, layout, implib + тесты на синтетических/собственных
образах), `x2x-loader` (prepare, map, bind, TLS-редирект, заглушки,
crash-репортер, потоки), CLI `inspect`, `census`, `lib-exports`, `config`.
Тесты на probe-фикстуре: не-PE DLL именуется в ошибке; prepare не исполняет
код; импорты биндятся через resolver; TLS exe-как-DLL редиректится.

**Приёмка:** `census` по реальным файлам пользователя (если даны)
классифицирует импорты без запуска; probe-тесты зелёные; crash-репортер
именует fault `module+rva` на синтетическом краше.

### Фаза 2 — HLE-ядро: загрузка до первых экранов

Модули: `kernel`, `files`, `xgameruntime` (области пользователей,
лицензий, пакетов), `xuser`, `xpackage`, `xgamesave` (crash-safe!),
`xgameui`, `lifecycle`, `xasync`, `xmem`, `rpcrt4`, `net`, `display`,
`storage`. HostPolicy. Виртуальные диски. Сейвы переживают kill на любом
шаге.

**Приёмка:** тайтл пользователя грузится до первых экранов (доступность,
язык, настройки, правовые) на 30 fps; сейв переживает kill -9 в любой
момент записи; `census --missing` показывает остаток.

### Фаза 3 — Форматы, стриминг, аудио, ввод

`x2x-formats` (texture, bcpack + таблицы-исключение, xma, opus, zlib),

**Приёмка:** вступительное видео со звуком; стартовый экран, профиль,
сейвы; загрузка в мир (~50 с у образца); меню со звуком; геймпад и
клавиатура работают.

### Фаза 4 — GPU и шейдеры: меню

`x2x-gpu` (device, dxgi, resource, fence, queue, list, descriptor, root,
pipeline, frame, object, console), `x2x-shader` (dxbc, dxil, gfx10, ir,
structure, range, resource, emit), `d3d12x`, `xg`. Кэш шейдеров
(SOURCE_HASH), `translate --cache`. Тесты шейдеров против float-режима
консоли, валидация dxil.dll.

**Приёмка:** меню рисуются, compute и presentation на host D3D12;
копируется только изменённая память тайтла; все шейдеры меню
транслированы; 30 fps; `translate --validate` валидирует SM 6.6.

### Фаза 5 — Мир

Bindless, page table title memory, shadow-копии и журнал изменений,
twin-текстуры, indirect, mesh-пайплайны, библиотека пайплайнов
(`translate --cache --pipelines`), `x2x-title` (shaderpack, sgd5,

**Приёмка:** мир рисуется и показывается (улицы, здания, транспорт,

### Фаза 6 — Точность и скорость: playable

Освещение, недостающая геометрия, merged geometry stages (195 программ),
оставшиеся ~100 шейдеров, 64-лейновые waves на любом GPU, метаданные
render-target, настоящие queries, depth bounds, HDR, масштабирование,
frame pacing без дрейфа, скорость кадров мира → реальные 30/60 fps.
Верификация Opus против тайтла. Речь, реверберация, вибрация триггеров.

**Приёмка:** мир играбелен на машине пользователя; кадр ≤ 33 мс (30 fps)
в типичной сцене; освещение корректно; `translate` покрывает 100% шейдеров
тайтла (или каждый остаток объяснён и записан).

### Фаза 7 — «Даже больше»

Раздел 15: мир Series S, мульти-тайтловость (test_titles), инструментарий,

## 7. Стандарты кода

* **Toolchain:** pinned в `rust-toolchain.toml` (образец: 1.98.1, targets
  x86_64-pc-windows-msvc, components rustfmt+clippy, profile minimal).
  Edition 2024, rust-version 1.88. MSVC C++ build tools обязательны для
  сборки.
* **Формат:** `cargo fmt --all` (100 колонок, field-init shorthand).
* **Линты workspace:** `unsafe_op_in_unsafe_fn = "deny"`,
  `unused_must_use = "deny"`; clippy `all = warn`,
  `undocumented_unsafe_blocks = warn`. CI требует `-D warnings` в обеих
  конфигурациях фич.
* **unsafe:** каждый `unsafe`-блок несёт `// SAFETY:` комментарий, почему
  он sound. HLE-экспорты — `extern "system"` с точным ABI; модули могут
  `#![allow(non_snake_case)]` для Win32-имён и
  `#![allow(clippy::not_unsafe_ptr_arg_deref)]` там, где тайтл передаёт
  указатели, которым настоящий API доверял бы.
* **Ошибки:** `thiserror` в библиотечных крейтах, `anyhow` с контекстом в
  apps и xtask. Громко падай на границах; доверяй внутренним инвариантам.
  Никаких `unwrap()` в путях, достижимых из тайтла.
* **Доки:** `//!`-доки модулей объясняют роль и контракт (образец —
  `victory-hle/src/lib.rs`, `victory-loader/src/lib.rs`). Комментарии —
  почему, не что. Doc-комментарии фиксируют контракты и краевые случаи.
* **Идиомы:** edition 2024 (let-chains и друзья) — домашний стиль.
* **Профили:** `profile.dev.package."*"` opt-level 2 (зависимости — горячие
  пути при переваривании гигабайт данных); `profile.release` debug =
  line-tables-only; `profile.diag` inherits release + фича `diagnostics`,
  отдельная папка, чтобы не вытеснять release.
* **Маленькие шаги:** один PR — одна фича/фикс. Никаких drive-by
  рефакторингов, никакого переформатирования чужого кода.

## 8. Тестирование

* **Весь набор проходит без файлов игры и без GPU.** Тесты, которым нужны
  реальные файлы, берут пути из переменных окружения и скипаются, когда
  те не заданы; аппаратные тесты печатают `... skipped`, когда нет SM 6.6
  устройства. Тест, требующий игру или GPU для прохода, — баг.
* **Только синтетические фикстуры;** ассертим свойства, никогда —
  снапшоты игровых данных. Loader-тесты — на probe-фикстуре.
* **Шейдерные тесты** (`emit/*_tests.rs` образца): семантика инструкций и
  control flow против float-режима консоли; waterfall-тесты требуют
  device readback; hardware-проверки скипаются без GPU. Валидация
  SM 6.6-контейнеров через `dxil.dll`: если старый SDK-валидатор
  отвергает `ps_6_6`, задай `X2X_DXIL` путь к актуальному x64 `dxil.dll`
  (релиз DXC или свежий Windows SDK) и беги
  `cargo test -p x2x-shader --lib --locked -- --test-threads=1`.
* **Что тестировать в каждой подсистеме:** policy (отказы путей), prepare
  (не исполняет код), resolver (порядок, override, Missing), сейвы
  (kill на каждом шаге), texture layouts (против addrlib-размеров),
  шейдеры (каждая инструкция — пиннинг семантики), кэш (ключи,
  детерминизм, атомарность), indirect (бюджет, порядок), GPU-объекты
  (контракты методов).
* **Регрессии:** каждый баг-фикс получает тест, который без фикса падает.
  «Починил и проверил глазами» — не готово.

## 9. Сборка и CI

CI (`.github/workflows/ci.yml`) на `windows-latest`:

```sh
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo test --workspace --locked        # включает repository_passes_policy
```

Локально повторяй то же плюс fmt и policy. Обе clippy-конфигурации важны:
фича `diagnostics` гейтит реальные пути кода.

Сборки:

```sh
cargo build --release -p x2x                          # target/release/x2x.exe
cargo build --profile diag -p x2x --features diagnostics   # target/diag/x2x.exe
```

Требования машины: Windows 10/11 x64, CPU с AVX2, D3D12 GPU с SM 6.6 (и
mesh shaders для мира), несколько GiB свободного Windows commit при
старте (Task Manager → Performance → Memory → Committed; ошибка 1455 в
`crashes.log` — закрой приложения или увеличь файл подкачки).

### 9.1 Прогресс и Pages

Прогресс считается из кода, не из запуска игр, и ничего не говорит о том,
запускается ли тайтл. Три метрики:

* **HLE exports** — поверхность parity-цели: объявленные регистрации
  `hle_export!(Name)` эталонного слоя (`tools/hle_surface.txt`) против наших
  `crates/x2x-hle/src/modules`. Экспорт реализован, если тело нашего `fn Name` —
  не заглушка (заглушка только возвращает `E_NOTIMPL`, зовёт `missing` или
  является `unimplemented!`/`todo!`). Тотал — поверхность эталона, поэтому вся
  запланированная поверхность видна как todo, пока не реализована.
* **GFX10 opcodes decoded** — таблицы декодера
  `crates/x2x-shader/src/gfx10/opcodes.rs` против списка AMD RDNA 1 + RDNA 2
  (`tools/rdna_isa.txt`, MIT-notice AMD сохраняется дословно). Decoded ≠
  транслировано в DXIL.
* **D3D12.X methods** — поверхность vtable эталонного слоя
  (`tools/d3d12x_surface.txt`) против слотов, подключённых к настоящим функциям
  в `crates/x2x-gpu/src`; базовые методы объекта считаются тоже. Неподключённый
  слот логирует и падает, поэтому он не реализован. Тотал — поверхность
  эталона. Wired ≠ полное или корректное поведение метода на GPU.

`tools/progress.py` рендерит бейджи, treemap (`progress.svg`) и
`progress.html`; `tools/progress_history.py` — точку на UTC-день для
`history.html`. Скелет без крейтов меряется честно (exports 0/149, opcodes
0/тотал, D3D12.X 0/700). Workflow: `progress-report.yml` (PR-дельта base→head через
`--compare`), `progress-comment.yml` (комментарий в PR), `pages-progress.yml`
(push в main: перегенерация и деплой только при изменении `progress.json`),
`pages.yml` (полная сборка сайта, ежедневно и вручную). Бейджи и карта в
README ведут на `torvaldsdev.github.io/xbox2xbox`. Меняешь правила счёта —
обнови этот раздел и README; `rdna_isa.txt` не правь вручную.

## 10. Запуск тайтла

Только с файлами пользователя, настроенными вне репозитория:

```sh
copy x2x.example.toml x2x.toml     # затем задай пути (вне репо)
cargo run -p x2x -- config         # проверка путей
cargo build --release -p x2x
target/release/x2x.exe translate --cache --pipelines <game dir>/shaders.rpf <exe> <XboxBvhBuilder.dll> <amd_fidelityfx_upscaler_xbox.dll>
target/release/x2x.exe run <game dir>/<exe> --execute
```

* `translate --cache` греет кэш шейдеров (~1.3 ГБ); `--pipelines` собирает
  ~27 000 host-пайплайнов пакета (~20 мин на 16 потоках). Библиотека
  принадлежит GPU и драйверу, на которых сделана. Повторный прогон
  пропускает существующее за секунды; прерванный — сохраняет сделанное.
* Без прогрева шейдеры транслируются при первом использовании, и их draw
  ждут.
* Данные: `%LOCALAPPDATA%\xbox2xbox\data` (сейвы, настройки,
  `crashes.log`); производные — `%LOCALAPPDATA%\xbox2xbox\cache`.
* Series S: `run --console series-s`. FidelityFX: PC DLL через
  `X2X_FIDELITYFX_DIR` (папка `Kits/FidelityFX/signedbin` FidelityFX SDK с
  `amd_fidelityfx_upscaler_dx12.dll`); без неё или без upscaler под твой
  GPU — работают собственные DLL тайтла.
* `X2X_WINDOW_MAX=1920x1080` ограничивает окно тайтла bounding box'ом
  (масштабирует показ, не консольное разрешение рендера).
* Ввод: XInput; без геймпада клавиатура — геймпад, пока окно тайтла в
  фокусе (WASD/IJKL — стики, стрелки — D-pad, Enter/Backspace/X/Y —
  A/B/X/Y, Q/E/Z/C — shoulders/triggers, F/H — клики стиков, Esc/Tab —
  Menu/View).

**Анализ без запуска** — `inspect`, `census`, `shader-info`,
`translate --list/--validate` требуют только файлы пользователя, без GPU.
Предпочитай их, когда запуск невозможен: так верифицируется большая часть
платформенной работы.

## 11. Отладочный арсенал

Release-сборка не имеет отладочных средств. Встрой их:
`cargo build --profile diag -p x2x --features diagnostics`.

Полный арсенал переменных (все `X2X_*`, выключены когда не заданы или
`0`; зеркало README образца):

| Переменная | Эффект |
|-----------|--------|
| `X2X_LOG=<target>=debug,...` | debug/trace-вывод |
| `X2X_STACKS=20,60` | стеки всех потоков на этих секундах |
| `X2X_WATCH=<rva>,...` | лог u32 тайтла при изменении |
| `X2X_POKE=<rva>:<byte>,...` | запись байта тайтла дважды в секунду (тик watchdog'а зависания) |
| `X2X_KEYS=30:Enter,35:X` | нажатия клавиш на этих секундах, в фокусе или нет |
| `X2X_CRASH_BREAKPOINTS=1` | first-chance breakpoints в `crashes.log`, включая восстановимые |
| `X2X_CRASH_SAVE=<rva>:<len>,...` | память тайтла в cache-папку при краше |
| `X2X_CAPTURE=<dir>` | сохранение показанных кадров (степени двойки, или `X2X_CAPTURE_FRAMES=<list>`) |
| `X2X_DUMP_TARGETS=1` | с двумя выше — все render targets этих кадров |
| `X2X_CAPTURE_WORLD=<list>` | с `X2X_CAPTURE` — кадры на этих смещениях от первого кадра с 500 draw (первый кадр мира) |
| `X2X_DUMP_WRITERS=<hash>,...` | текстуры, которые пишет пайплайн с listed shader hash, первый кадр, и лог по буферам (изменённые/ненулевые dwords) |
| `X2X_PEEK=<hex addr>[:<bytes>],...` | в listed кадрах — байты памяти тайтла после каждой submission; мелкие targets как значения, view words таблиц, host-копии мелких буферов, readback 1D/3D текстур после dispatch |
| `X2X_D3D12_DEBUG=1` | host debug layer |
| `X2X_D3D12_GBV=1` | с выше — GPU-based validation (медленно) |
| `X2X_D3D12_DRED=1` | при GPU failure — задетая аллокация и команды в полёте |
| `X2X_SKIP_PIPELINES=<hash>,...` | пропуск draw/dispatch (включая indirect) пайплайна с listed 16-значным shader hash |
| `X2X_GPU_TIMING=1` | каждый список submission бежит и таймится отдельно; медленные списки с медленнейшими командами; device removal именует список |
| `X2X_TRACE_SHADERS=<hash>,...` | с DRED — каждый draw/dispatch listed шейдера с биндингами (user data, heap slots, root views и их первые dwords; первые 500) |
| `X2X_D3D12_WARP=1` | host-устройство на программном адаптере (медленно; не может сбросить драйвер) |
| `X2X_PIPELINE_LOG=<file>` | строка на созданный пайплайн (ключ, шейдеры, состояние), первое использование, сборка/загрузка |
| `X2X_PREBUILD_KEYS=<file>` | `translate --cache --pipelines` ничего не делает и перечисляет ключи записей пакета |
| `X2X_SHADER_LOOP_LIMIT=<n>` | циклы трансляций стоп после n итераций на лейн вместо 2^20; если меньший n сильно ускоряет кадры мира — медленные циклы упираются в лимит |
| `X2X_AUDIO_CAPTURE=<file.wav>` | запись того, что играет тайтл (только наш процесс) |
| `X2X_XMA_DUMP=<dir>` | контекст и вход первых 32 XMA-голосов |

Каждая сборка аппендит необработанные исключения, паники и host GPU
failures в `crashes.log` в data-папке тайтла.

**Рабочий цикл для рендер-дефекта:**

1. Читай `crashes.log` первым — fault именован `module+rva` со стеком.
2. Захвати кадры: `X2X_CAPTURE` (+ `X2X_DUMP_TARGETS`,
   `X2X_CAPTURE_WORLD` для первых кадров мира).
3. Бисектируй draw: `X2X_SKIP_PIPELINES` пропускает draw пайплайна;
   `X2X_DUMP_WRITERS` показывает, что пишет шейдер.
4. Инспектируй состояние: `X2X_PEEK`, `X2X_WATCH`/`X2X_POKE`,
   `X2X_KEYS`, `X2X_STACKS`.
5. GPU-правда: `X2X_D3D12_DEBUG`, `X2X_D3D12_GBV`, `X2X_D3D12_DRED`,
   `X2X_GPU_TIMING`, `X2X_TRACE_SHADERS`.
6. Медленные кадры мира: `X2X_SHADER_LOOP_LIMIT`.
7. Аудио: `X2X_AUDIO_CAPTURE`, `X2X_XMA_DUMP`.

Сравнивай hardware и WARP-прогоны по module+offset исключения, стекам и
предшествующим сообщениям. Отказ host-DLL включает стек вызывающего в
консоль; отказ ожидаем для DLL вне host-политики, включая `rpcrt4.dll`.

## 12. Git workflow

* Subject коммита: `Area: одно простое предложение о изменении поведения`.
  Реальные примеры из истории образца:
  * `GPU: a marked page's copy-back does not save the page for its own copy`
  * `Shaders: honor op_sel, omod and clamp on v_interp_p2_f16`
  * `HLE: guard dialog commands before initialization`
  * `Loader: guard clwb_loop shortcut against u64 overflow and wraparound`
  Области: GPU, Shaders, HLE, Loader, Tests, Audio, XMA, XGameSave,
  Formats, Diagnostics, CLI, README, …
* Работа на ветке (`fix/…`, `perf/…`, или имя области), PR в `main`; CI
  обязан пройти. Никогда не пушь напрямую в `main`, никогда не
  force-push'ь его.
* Pre-commit hook гоняет политику ассетов. Если он блокирует — коммит
  содержит то, чего не должен: чини содержимое, никогда не обходи хук.
* Держи диффы сфокусированными. Никаких drive-by рефакторингов.
* Никогда не коммить файлы с секретами; `x2x.toml` (пути пользователя)
  игнорируется git.

## 13. Definition of done

Прежде чем назвать изменение законченным:

* [ ] `cargo fmt --all` чистый; обе clippy-команды чистые; `cargo test
      --workspace --locked` зелёный; `cargo xtask policy` проходит.
* [ ] Изменения поведения запиннены синтетическим тестом или верифицированы
      прогоном, подтверждения которого (строки лога, захваченные кадры вне репо) ты
      можешь привести. «Компилируется» — не верификация.
* [ ] Новые игро-зависимые тесты чисто скипаются без путей/GPU.
* [ ] Никаких игровых байтов в диффе — включая доки, тесты и сообщения
      коммитов.
* [ ] README-статус обновлён, когда milestone сдвинулся; architecture.md —
      когда структура изменилась.
* [ ] Платформенный код остался тайтл-агностичным; игровое знание — только
      в `x2x-title`.
* [ ] Known-упрощения записаны в список (раздел 15), не замаскированы.

## 14. Кодекс агента

* **Изучай, прежде чем писать.** Прочитай соответствующий модуль образца
  целиком (не выдержки), проследи фичу (раздел 3.3), выпиши контракт.
  Не изобретай API: сверяйся с документацией Microsoft/GDK; грепай, прежде
  чем предполагать, что хелпер существует.
* **Verify, don't invent.** Утверждение о платформе Xbox подкрепляй
  источником: код образца, документация, наблюдение прогона. «Наверное,
  консоль делает так» — не источник.
* **Спрашивай владельца перед:** запуском тайтла на реальном GPU, долгими
  сборками, чем-либо деструктивным, перезаписью истории, force-push,
  переносом BCPack-таблиц, новой внешней зависимостью, отклонением от
  blueprint.
* **Никогда не ослабляй** политику ассетов, host-политику DLL или
  offline-гарантию, чтобы что-то заработало. Если фикс, кажется, требует этого —
  фикс неправильный.
* **Отчитывайся честно.** Мир образца рендерится 1–2 с/кадр с дефектами;
  говори, что реально наблюдал, а не что надеялся увидеть. Статус «не
  играбельно» — текущая правда; не заявляй иного без evidence.
* **Формат отчёта владельцу:** что сделано (файлы, крейты), evidence
  (тесты, логи, кадры), что осталось до критериев фазы, следующий шаг.
  Коротко, по делу, без воды.
* **Застрял на рендер-дефекте** — пройди debugging playbook сверху донизу,
  прежде чем гадать. Инструменты существуют; используй их.
* **Один шаг за раз.** Маленький законченный инкремент лучше большого
  недоделанного гиганта. Каждый инкремент проходит definition of done.

## 15. «Даже больше»: цели превосходства

Паритет — минимум. После паритета каждой подсистемы закрывай её долги и
превосходи образец. Конкретные цели (из «Needs» образца + наши):

| Ось | Образец сегодня | Наша цель |
|-----|-----------------|-----------|
| Скорость мира | 1–2 с/кадр | ≤ 33 мс (30 fps) в типичной сцене; 60 fps — stretch |
| Освещение | поверхности unlit | корректное освещение мира |
| Геометрия | полоса дальней геометрии отсутствует, персонажи местами сломаны | полная геометрия, целые персонажи |
| Шейдеры | mesh 8765/8765, VS/PS 12550/12592, compute 2579/2637; merged geometry 195 + ~100 других | 100% покрытие тайтла; каждый остаток объяснён |
| Waves | часть compute требует 64-лейновый GPU | работает на любом SM 6.6 GPU (эмуляция 64-лейновых waves там, где хост 32) |
| Текстуры | нет метаданных render-target planes | метаданные поддержаны |
| GPU-фичи | нет настоящих queries, depth bounds, HDR, масштабирования | всё поддержано |
| Frame pacing | дрейф на одном экране в release | без дрейфа везде |
| Аудио | речь молчит, реверберация молчит, Opus не верифицирован | речь и реверберация работают; Opus верифицирован против тайтла |
| Ввод | нет вибрации триггеров | trigger rumble работает |
| Series S | только до loading screen | мир играбелен |
| Тайтлы | один (GTA VI) | платформенный код проверен на ≥ 2 дополнительных тайтлах (`test_titles`) |
| Инструментарий | богатый, но ручной | автоматический регрессионный harness: census-покрытие, translate-покрытие, захват эталонных кадров вне репо, сравнение свойств |

**Список known-упрощений** (веди в `docs/shortcuts.md`, создай в фазе 0):
каждый перенесённый из образца `shortcut:` и каждое наше осознанное
упрощение — записью: что упрощено, почему допустимо сейчас, что сломается,
когда станет недопустимо. Пустой список — ложь; замаскированное
упрощение — долг, который взорвётся.
